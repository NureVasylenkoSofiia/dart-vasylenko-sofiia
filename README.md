# Розклад занять групи — Dart

**Лабораторна робота №1. Функції та обробка колекцій**

**Виконала:** Василенко Софія Олександрівна, ПЗПІ-23-3  
**Предметна область:** Розклад занять групи

### Опис програми

Консольний застосунок для обробки розкладу занять університетської групи. Програма читає набір текстових записів, перевіряє їх коректність, виконує фільтрацію, групування, сортування та формує текстовий звіт.

Кожне заняття містить назву дисципліни, викладача, тип заняття, день тижня, час початку, аудиторію та дату проведення.

Початкові дані складаються з 15 записів, серед яких три навмисно пошкоджені для демонстрації обробки помилок.

### Структура проєкту

- `bin/group_schedule.dart` — точка входу, запуск усіх операцій та виведення результатів.
- `lib/schedule_data.dart` — константний список вхідних записів.
- `lib/schedule_parser.dart` — типізований запис `ScheduleEntry` і функція розбору.
- `lib/schedule_validator.dart` — перевірка правил предметної області.
- `lib/schedule_statistics.dart` — фільтрація, агрегування, групування та сортування.
- `lib/schedule_report.dart` — формування текстового звіту.
- `lib/schedule_utils.dart` — замикання, перевірка аудиторії, маскування та робота з датами.
- `test/` — каталог для тестів.
- `analysis_options.yaml` — правила статичного аналізу.
- `analyze_result.txt` — збережений результат команди `dart analyze`.

Логіку винесено до `lib/`, щоб її можна було повторно використовувати й перевіряти незалежно від консольного інтерфейсу. У `bin/` залишено точку входу програми.

### Вибір типів даних

Для вхідного набору використано `const List<String>`, оскільки за умовою лабораторної записи мають бути представлені рядками з роздільником.

Для структурованих занять використано Dart Records із псевдонімом типу `ScheduleEntry`. Це дозволяє зберігати поля з конкретними типами без створення власного класу, що відповідає обмеженню ЛР1.

Час початку представлено типом `int` як кількість хвилин від початку доби, щоб спростити порівняння та сортування. Дата представлена типом `DateTime`.

Для групування використано `Map<String, List<ScheduleEntry>>`, де ключем є день тижня, а значенням — список занять. Для унікальних дисциплін застосовано `Set`, що усуває повторення.

### Основні рішення

Розбір рядків реалізовано через `split()`, `int.tryParse()` та `DateTime.tryParse()`. У разі некоректного формату функція повертає `null`, а не завершує програму з помилкою.

Окремий валідатор повертає список порушень для кожного структурованого запису.

Для обробки колекцій використано `where()`, `map()` і `fold()`. Групування виконується через `Map`, а сортування — через `sort()` із параметром `ascending`.

Формування звіту реалізовано через `StringBuffer`, щоб не створювати багато проміжних рядків.

Замикання `createRecordCounter()` захоплює змінну `count` і зберігає її значення між викликами. Воно використовується для нумерації оброблених записів.

Регулярний вираз із іменованими групами перевіряє формат аудиторії. Метод `replaceAllMapped()` частково маскує номер. Різниця між датами обчислюється через `DateTime.difference()` та `Duration`.

### Залежності та альтернативи

Проєкт використовує стандартні можливості Dart без додаткових бібліотек для обробки розкладу.

У стандартному шаблоні Dart підключені пакети `lints` і `test` як залежності для розробки. `lints` використовується для перевірки стилю коду відповідно до Effective Dart, а `test` — для автоматизованих перевірок.

Як альтернативу `lints` можна було використати суворіші правила аналізатора, але для цієї роботи обрано рекомендований набір, якого достатньо для вимог методички. Альтернативою пакету `test` є ручні перевірки через `assert`, однак пакет забезпечує зручнішу структуру тестів.

Для парсингу можна було використати сторонній CSV-пакет, але дані мають простий фіксований формат без екранованих роздільників, тому `split()` є достатнім рішенням.

Замість Records у майбутньому можна використати класи. Це буде доцільно в ЛР2, де передбачено об'єктно-орієнтовану реалізацію.

### Null safety

У реалізації не використовуються `late` та `dynamic`, оскільки всі необхідні значення можна представити конкретними типами або nullable-типами.

Оператор примусового розпакування `!` не застосовується. Для nullable-значень використано перевірки на `null`, оператор `??` і безпечний доступ `?.`.

Оператор `as RegExpMatch` використано для явного приведення типу результату регулярного виразу, необхідного для доступу до іменованих груп.

### Запуск

Встановити Dart SDK 3.13 або новішої версії.

У кореневій папці проєкту виконати:

```powershell
dart pub get
dart run
```

Для форматування та перевірки коду:

```powershell
dart format .
dart analyze
```

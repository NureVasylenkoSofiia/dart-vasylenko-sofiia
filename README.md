# Розклад занять групи

Консольний проєкт мовою Dart для роботи з розкладом занять університетської групи. Розробляється в межах лабораторних робіт із дисципліни «Програмування мовою Dart».

Василенко Софія Олександрівна, ПЗПІ-23-3.

### Про програму

У першій лабораторній роботі реалізовано обробку розкладу без використання власних класів. Програма працює з 15 текстовими записами, три з яких навмисно містять помилки. Після розбору й перевірки даних виконуються фільтрація, групування за днями тижня, сортування за часом та дисципліною, підрахунок статистики й формування текстового звіту. Додатково реалізовано перевірку формату аудиторій, маскування їхніх номерів і обчислення різниці між датами.

### Реалізація

Точка входу знаходиться в `bin/group_schedule.dart`, а функції обробки даних винесені до `lib/`. Так основна програма не містить усієї логіки в одному файлі, а окремі функції можна повторно використовувати й перевіряти. Початкові записи зберігаються у `schedule_data.dart`, розбір виконується у `schedule_parser.dart`, перевірка — у `schedule_validator.dart`. Для статистики та сортування використовується `schedule_statistics.dart`, для текстового звіту — `schedule_report.dart`, а допоміжні функції знаходяться у `schedule_utils.dart`.

Вхідні дані представлені як `const List<String>`, оскільки за умовою роботи вони мають бути текстовими рядками з роздільником. Після розбору використовується типізований Dart Record `ScheduleEntry`. Це дозволяє звертатися до полів за назвами й не створювати власний клас, який у ЛР1 не передбачений. Альтернативою є окремий клас для заняття, який планується реалізувати в наступній лабораторній роботі.

Час початку зберігається як `int` — кількість хвилин від початку доби, що спрощує сортування. Для дат використано `DateTime`, для групування — `Map<String, List<ScheduleEntry>>`, а для отримання унікальних назв дисциплін — `Set<String>`. Замість ручного пошуку повторень `Set` дозволяє одразу отримати унікальні значення.

Для розбору застосовано `split()` і `tryParse()`, щоб некоректні записи не спричиняли аварійного завершення. Обробку колекцій реалізовано через `where()`, `map()` та `fold()`. Сортування виконується над копією списку, щоб не змінювати початкові дані. Для формування тексту використано `StringBuffer`, а для нумерації записів — замикання, яке зберігає значення лічильника між викликами. Перевірка аудиторії використовує `RegExp` з іменованими групами та `replaceAllMapped()`, а арифметика дат — `DateTime.difference()` і `Duration`.

### Залежності

У програмі не використовуються `late` та `dynamic`, оскільки всі значення мають визначені типи. Оператор `!` застосовується для логічного заперечення у перевірці `!isValidRoom(entry.room)`, щоб визначити, чи має аудиторія неправильний формат. Для примусового розпакування nullable-значень `!` не використовується — замість цього застосовано перевірки на `null`, а також оператори `??` і `?.`. У функції маскування використано `as RegExpMatch`, оскільки для доступу до іменованих груп регулярного виразу потрібен саме цей тип.

Також розглядалося використання готового CSV-парсера, проте для фіксованого формату із сімома полями достатньо звичайного `split()`, тому додавати окрему бібліотеку немає потреби.

Для основної логіки програми додаткові пакети не використовуються. У `pubspec.yaml` залишено стандартні залежності для розробки: `lints` для перевірки стилю коду та `test` для автоматичного тестування в наступних лабораторних роботах. Замість `lints` можна було налаштувати власні правила аналізатора, а для простих перевірок використовувати `assert` замість пакета `test`. Проте я залишила стандартні залежності, оскільки вони підходять для подальшого розвитку проєкту.

### Запуск

Для роботи потрібен Dart SDK 3.13 або новішої версії. Команди виконуються з кореневої папки проєкту:

```powershell
dart pub get
dart run
dart format .
dart analyze
```

У результаті обробки 15 записів програма приймає 12 і відхиляє три. Серед коректних записів визначено чотири лабораторні заняття та шість унікальних дисциплін. Остання перевірка `dart analyze` завершилася без зауважень (`No issues found!`).
